# 网易云音乐助手 · RE

NeteaseMusicAssistant 是面向 Windows 与 Microsoft Edge 的网易云音乐图形工具，提供扫码登录、签到、歌单任务、单曲/多曲次数与循环管理。项目参考了 [cwuom/netease-cloud-LV10](https://github.com/cwuom/netease-cloud-LV10) 的功能思路，公开版本采用本次重新实现的 Python 代码。

## 使用 EXE

1. 将 `NeteaseMusicAssistant.exe` 放在可写入的文件夹中，双击打开，无需安装 Python 或 Node.js。
2. 点击“检查连接”。随附的本地接口在后台启动，退出软件时会关闭由本软件启动的接口进程。
3. 点击“扫码登录”，用网易云音乐 App 扫描 Edge 中打开的二维码，并在手机上确认。二维码过期后重新点击登录。
4. 填入歌单 ID；留空时使用自己创建的第一个歌单，通常是“我喜欢的音乐”。
5. 自定义每轮歌曲数，范围 **1–250 首**，默认 20 首。点击“开始上报”。
6. 分别查看“本轮上报受理”和“本轮实际增量”。已受理不代表一定计入等级，最终结果取决于网易云服务端。

“立即签到”分别请求安卓和网页签到。重复签到会显示“已签到”。“查看统计”读取累计听歌量、当前等级和升级条件。定时运行采用 UTC+8，需要保持软件开启；登录失效时需重新登录。

### 单曲/多曲次数与循环轮数

将“运行模式”切换为“单曲/多曲次数”，填写一个或多个歌曲 ID，用逗号、空格或换行分隔。也可以点击“编辑歌曲列表”，一行填写一个 ID。重复的 ID 会合并，一次最多选择 250 首。

设置“每首每轮次数” **1–100 次**、“循环轮数” **1–1000 轮**，以及“同时处理首数” **1–8 首**，默认同时处理 3 首。实际并行数不会超过已选歌曲数。一轮内所有歌曲完成后才会进入下一轮。

例如，选择 3 首歌曲，每首每轮 10 次、循环 2 轮，则本次计划上报 **3 × 10 × 2 = 60 次**。界面会在开始前显示这个计划。每次任务有独立进度记录，不会自动重试结果不明的写入。点击“停止”后不再开始新的上报，已发送的请求会等待返回并记录结果。

“歌曲结果”页逐首列出受理数、未确认数、原周次数、现周次数和实际增量；“运行日志”显示每首歌曲所处的轮次和次数。某首歌曲失败时，结束后续歌曲与轮次，已经发送的并行请求仍会正常记录结果。

次数增量读取所选歌曲在当前账号周播放排行中的 `playCount` 前后变化，与等级累计听歌量分开显示。歌曲不在可见的周排行或排行不可读时显示“未核验”，不会将接口受理次数直接当作播放次数增长。

歌单模式也支持循环轮数，继续使用当天去重和 250 首上限。没有新歌曲、达到上限或遇到失败时会提前结束循环。“立即签到”功能保持独立，循环轮数指听歌上报循环。

### 登录兼容性

初次手机验收曾出现二维码立即失效；修正 POST 接口缓存和网页版二维码参数后，重新扫码已完成真实账号登录，并读取到等级及累计听歌量。过期的旧页面不能复用，请以每次点击“扫码登录”后新打开的页面为准。

Windows 10/11 x64，需已安装 Microsoft Edge。首次启动单文件 EXE 需要解压内置运行时，可能比后续启动稍慢。程序会在 EXE 旁创建 `.state` 保存设置、进度和诊断日志，因此请放在自己可写入的目录中。

## 这次修改

- 原源码只包含三个依赖外部 Node API 的 Python 脚本；README 中描述的打包版浏览器功能并未包含在该分支源码中。本版本重新提供 Edge 扫码入口，不依赖固定浏览器版本或驱动。
- 使用已核对的 API Enhanced 4.41.1，并固定 npm 锁文件。自动模式优先使用 `/scrobble/v1`；只有明确返回 404/405 才退回旧 `/scrobble`，超时、认证失败或其他异常不会触发重复写入。
- 修复登录状态解析死循环、部分模式遗漏签到、Cookie 解析、歌曲时长截断、无限线程、无限轮询、递归重试和危险的强制终止线程。
- 单个后台任务管理运行；歌曲次数模式最多并行处理 8 首，界面可停止；读取失败有限重试，签到/上报不自动重试。
- 每轮数量可自定义，上限 250；同账号同天总尝试数量也限制为 250，按歌曲 ID 去重。继续运行会跳过当天已尝试歌曲并推进到后续歌曲。
- 请求前保存待确认进度，避免中断后重复上报。失败或响应不明的歌曲当天不会自动再试。
- 用服务端累计听歌量的前后差值核验增长，并读取等级信息。该差值也可能包含同账号在其他设备上的播放，不能精确证明每一条上报都计入等级。
- Windows 使用 DPAPI 保护已保存的登录信息；如果当前环境无法加密保存，则只保留本次会话，界面明确提示下次需重新登录。
- 本地接口只监听 127.0.0.1；Cookie 放在请求正文，报告不写 Cookie，也不上传到开发者服务。

## 设置与排查

“设置”可更改 API 地址、请求间隔、统计核验等待时间和上报方式。默认本机地址 `http://127.0.0.1:3000`；远程接口必须使用 HTTPS。

累计听歌量不增长时，程序会显示 0 增量并结束本轮，不会自动反复重刷。可稍后点击“查看统计”，确认是否存在延迟。此版本不承诺旧 README 中的“几分钟稳定 300 首”或必定升级。

如果 3000 端口已有服务，本软件会使用已有服务；不兼容时请关闭旧服务或在设置中选择自己的接口地址。关闭窗口时会等待当前网络请求结束，随后清理本软件启动的后台服务。

本机状态位于 `.state`；`last-report.json` 为最后一轮报告，`progress-用户ID-日期.json` 为每日去重进度，`api.log` 为本地接口诊断日志。请勿将 `.state`、真实 Cookie 或浏览器配置上传/分享。

## 源码运行与构建

Python 3.10+、Node.js 22+（构建机实测 Python 3.12.10、Node.js 26.5.1）。

```powershell
# 安装本地接口，保留锁文件
cd api-server
npm ci --ignore-scripts
cd ..

# 图形界面，Windows 用 pythonw 避免命令行窗口
pythonw app.py

# 回归测试
python -m unittest discover -s tests -v

# 打包单个无控制台 EXE
python -m pip install -r requirements-build.txt
python -m PyInstaller --noconfirm assistant.spec
```

源码同时保留可选诊断入口：`python -m ncm_tools doctor`。直接网站 WebDriver 登录仅作为源码备用功能，需额外安装 `requirements-webdriver.txt`；EXE 默认使用无需驱动的 Edge 扫码登录。
